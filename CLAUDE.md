## Overview

**n1qn1** (repository `n1qn1c`) is an R port of the Scilab `n1qn1`
module: unconstrained quasi-Newton BFGS optimization that can take a
user-supplied (compressed) starting Hessian. The numerical core is C
code produced by `f2c` from the Scilab Fortran and then hand-edited, so
the package has no Fortran sources. A thin C++/RcppArmadillo layer
connects R (or compiled) objective/gradient functions to the C core.
It is used by nlmixr2est, which links to it through a function-pointer
table (see below).

- License: CeCILL-2 (`LICENCE`, `inst/COPYING`)
- Imports: Rcpp; LinkingTo: Rcpp, RcppArmadillo
- Exports only `n1qn1()` and `.n1qn1ptr()`
- testthat edition 3, roxygen2 8.1.0

## Architecture

### Call path

1. `n1qn1()` (`R/n1qn1.R`) coerces arguments to integer/double,
   computes `nzm = ceiling(n * (n + 13) / 2)`, picks `mode`
   (1 = no Hessian, 2 = `zm` supplied, 3 = `restart=TRUE`), checks the
   length of `zm`, then calls `.Call(n1qn1_wrap, ...)` (13 args).
2. `n1qn1_wrap()` (`src/RcppExpMod.cpp`) validates `n`/`nzm` (including
   an `n * (n + 1)` int overflow guard) BEFORE allocating, wraps the
   objective/gradient in `Rcpp::EvalStandard` (R function) or
   `Rcpp::EvalCompiled` (external pointer) from `src/evaluate.h`, and
   passes the static callback `fwrap()` to the C core.
3. `n1qn1_()` / `n1qn1a_()` / `majour_()` (`src/n1qn1_all.c`) run the
   BFGS iterations; helpers `ajour_`, `calmaj_`, `proj_`, `satur_` live in
   their own f2c-translated files.
4. On return, the LDL' factor in `zm` is converted to the full Hessian
   `H` and its lower triangle `c.hess` with Armadillo. The result list is
   `value`, `par`, `H`, `c.hess`, `n.fn`, `n.gr`. With `assign=TRUE`
   the R wrapper stores `c.hess` in `environment`.

### Thread safety

Per-call state in `src/RcppExpMod.cpp` (`fev`, `gev`, call counters,
print flag) is `thread_local`, and `static` locals were removed from
the translated C code. Do not reintroduce file-level mutable globals or
`static` locals in `src/*.c`. `EvalBase` has a virtual destructor
because callbacks are deleted through a base pointer -- keep it.

### Function-pointer API for downstream packages

`_n1qn1_ptr()` in `src/init.c` (R: `.n1qn1ptr()`) returns a named list
of external pointers: index 0 `n1qn1F`, 1 `n1qn1F2`, 2 `n1qn1_`.
`inst/include/n1qn1c.h` declares the matching typedefs, the
`iniN1qn1c` macro and `iniN1qn1cPtrs0()`, which installs the pointers in
a downstream package (this lets nlmixr2est avoid ABI coupling and
re-submission when n1qn1 changes). The same three functions are also
registered with `R_RegisterCCallable`.

- Treat the table as APPEND-ONLY: never reorder, rename, remove, or
  change the signature of an existing slot; add new entries at the end
  and bump `nVec` plus the header together.
- Changing `inst/include/n1qn1c.h` affects packages compiled against it;
  do not change existing typedefs.

### `.Call` registration

`src/init.c` hand-maintains `R_init_n1qn1` and the `callMethods[]` table
with hardcoded argument counts (`_n1qn1_ptr` 0, `n1qn1_wrap` 13). There
is no `RcppExports.cpp`. If you change the arguments of `n1qn1_wrap`,
update the `extern` prototype and the count in `src/init.c` as well, or
the call fails at runtime with an argument-count error.

### Build configuration

`src/Makevars` and `src/Makevars.win` list sources explicitly
(`SOURCES_C`, `SOURCES_CPP`) and link `$(LAPACK_LIBS) $(BLAS_LIBS)
$(FLIBS)`. A new source file must be added to BOTH files.

## Testing

- Tests live in `tests/testthat/test-*.R`: `test-banana.R` (Rosenbrock
  reference), `test-coverage.R` (print/invisible paths, `EvalCompiled`
  via XPtr), `test-edge-cases.R`, `test-memory-safety.R`.
- `test-memory-safety.R` is excluded from the built tarball via
  `.Rbuildignore` (CRAN sanitizer machines flag its deliberate integer
  overflow). It still runs under `devtools::test()`. Do not remove that
  exclusion; keep overflow/large-`n` tests out of what CRAN runs.
- The Rosenbrock example in the `n1qn1()` docs is the canonical
  reference problem; reuse it for new tests.
- Assert on results (`par`, `value`, error messages), not on exact
  function-evaluation counts unless the existing tests already do.

## Code Style

### R
- Keep the public interface of `n1qn1()` stable; its argument names
  (`call_eval`, `call_grad`, `max_iterations`, `print.functions`, ...)
  and return-list names (`c.hess`, `n.fn`, `n.gr`) are relied on by
  downstream code.
- Internal helpers: `.camelCase` with a leading dot.
- Never use `pkg:::fun`; tests already run in the package namespace.

### C/C++
- The f2c-derived C files are not idiomatic C; make minimal, targeted
  edits and keep the Fortran calling convention (`int *` arguments for
  Fortran INTEGER).
- Validate inputs before any `new`/allocation in `n1qn1_wrap`, since
  `Rf_error` longjmps and would leak earlier allocations.
- Use strict prototypes (CRAN requirement).
- Printing must go through `Rprintf`, never `printf`/`stdout`.

### Documentation and text
- ASCII only everywhere (CRAN): use `--`, `->`, straight quotes.
- `NEWS.md` uses one `# n1qn1 X.Y.Z-N` heading per version with short
  bullet entries; add a bullet for user-visible changes.

## Release / CRAN Cautions

- nlmixr2est depends on this package; any change to the pointer table,
  `n1qn1c.h`, or the `n1qn1()` return value can break it on CRAN.
- Check with sanitizers (gcc-ASAN, valgrind) before submission; CRAN
  has requested these for this package.
- Do not add tests or examples that are slow, overflow integers, or
  depend on timing.

## CRAN tests: never assert on timing

- Never put a wall-clock timing expectation in a test that can run on CRAN:
  no `expect_lt()`/`expect_true()` on `Sys.time()` differences,
  `system.time()`, `proc.time()`, `bench`/`microbenchmark` results, or any
  other elapsed-time threshold. CRAN check machines are shared and heavily
  loaded, so elapsed time there is random and a timing assertion fails at
  random. Example: nlmixr2plot `test-model-diagram.R` asserted a
  `modelGraph()` call took < 30 s; on CRAN it took 48.4 s and failed.
- Test the result, not the speed. If a speed regression guard is really
  needed, put it only in a test that starts with `skip_on_cran()` (or the
  package's own CRAN skip helper), and never in examples or vignettes.
- Tests that take more than a few seconds should also skip on CRAN.
